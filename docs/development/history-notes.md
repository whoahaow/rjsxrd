# История репозитория: линия, вытесненная перезапуском

27 июня 2026 текущая история `main` началась заново — коммит `reinit` стал её
корнем. До этого у репозитория была другая история: 541 коммит с 9 декабря 2025
по 9 января 2026. Общего коммита у двух историй нет: `git merge-base main
refs/original/refs/heads/main` не возвращает ничего, то есть нынешний `main` не
происходит от той линии и не сливается с ней.

Ту историю удерживал указатель `refs/original/refs/heads/main` — имя, которое
оставляет за собой `git filter-branch`, когда переписывает ветку. Указатель не
был ни веткой, ни меткой, ни удалённым указателем: на него не ссылалось ничего,
и единственным его действием было не давать сборщику мусора удалить объекты той
линии. Ниже — что в ней было, почему её удалили и как её найти, если она
когда-нибудь понадобится.

Запись сделана до удаления указателя.

## Что в той линии было

- 459 из 541 коммитов — служебные обновления списков URL (`Обновление N.txt: <время> | <дата>`).
  Машина обновления та же, что и сейчас, отличаются только подписи коммитов.
- 14 файлов `source/` — предыдущее поколение кода на тех же путях, что и в текущем
  дереве: `config/settings.py`, `main.py`, `processors/config_processor.py`,
  `utils/file_utils.py`, `utils/github_handler.py`, `utils/logger.py`,
  `fetchers/{fetcher,daily_repo_fetcher,yaml_converter}.py` и `__init__.py`
  пакетов. Ни один блоб линии не совпадает с блобом `main` по тому же пути: это
  именно более ранние версии, а не копии.
- 7 файлов документации плоской структуры — `docs/overview.md`, `docs/technical.md`,
  `docs/installation.md`, `docs/index.md`, `docs/development.md`, `docs/faq.md`.
  В текущем дереве их нет: документация переехала в `docs/user/`,
  `docs/operation/` и `docs/development/` и была переписана.
- Раскладка `githubmirror/` того времени (`default/`, `split-by-protocols/`,
  `bypass-unsecure/`) — сейчас публикуется другая раскладка.
- Всего 34 пути, которых нет в текущем дереве (`git ls-tree -r --name-only` по
  линии против `git ls-files` на `main`).

## Проверки перед удалением

Перед тем как убрать указатель, проверено, что на него ничего не опирается:

- **Ветки.** `git for-each-ref` показывает три ссылки: `refs/heads/main`,
  `refs/original/refs/heads/main` и `refs/remotes/origin/main`. Ветки, ведущей в
  эту линию, нет.
- **Рабочие копии.** `git worktree list` — одна копия, на ветке `main`.
- **Метки.** `git tag -l` пуст.
- **Удалённые указатели.** `git ls-remote origin` отдаёт `HEAD`, `refs/heads/main`
  и четыре служебные ссылки `refs/pull/*`. Указателя на эту линию на удалённом
  репозитории нет.
- **Reflog.** Логи есть только у `HEAD`, `refs/heads/main` и
  `refs/remotes/origin/main`; ни одна запись не ссылается на коммиты линии
  (`grep <sha> .git/logs/...` не находит ни вершину, ни её предков).
- **Слияние.** `git merge-base` не возвращает общего коммита.

## Как восстановить содержимое

Объекты линии ещё отдаёт публичный `origin`: `GET /repos/{owner}/{repo}/commits/{sha}`
публичного GitHub API отвечает `200` для её коммитов с №1 по №539 — проверено
выборкой 18 сентября 2026 по позициям 1, 100, 200, 300, 400, 500, 505, 510, 515,
520, 525, 530, 535, 536, 537, 538, 539. Последние два коммита линии (№540 и
вершина №541) удалённый репозиторий уже не отдаёт: на запрос по их SHA приходит
`422` — в них правки, которые перед перезапуском не были отправлены. То есть
удалённый репозиторий хранит историю линии за вычетом последних двух коммитов, и
она читается по SHA, пока GitHub не собрал мусор у себя.

Проверить доступность любого коммита линии можно так:

```bash
curl -s -o /dev/null -w '%{http_code}\n' \
  https://api.github.com/repos/<owner>/<repo>/commits/<sha>      # 200 — коммит ещё есть
```
